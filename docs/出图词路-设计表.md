# 出图区词路设计表

> 2026-11-26 · 待确认后照此改 `buildSixRecipe()`。目标：把「选项 → 词」从一串 if 变成八层固定词路，位置和权重都有据可依。

## 一、总原则

1. **一层只说一件事**。同一层里互斥的选项只留一个说法，不准同时出现（现在服装 / 服装支 / 穿脱 / 裸体 / 淫水是同一件事的五个入口，靠一串 if 兜着）。
2. **手选在前带权重，随机补在后不带或压低**。用户没选的格子是系统替他抽的，不该跟手选平起平坐。
3. **tag 自带括号的不重复套**（萝莉 `(5 heads tall:1.3)` 这种），外层权重只给裸 tag。
4. **一层内部顺序固定**，不随代码书写顺序漂。
5. 权重上限 1.25。底模（Anima/Qwen）对超过 1.3 的叠加很敏感，容易出塑料或崩结构。

## 二、十层顺序

顺序 = 正面词从前往后的拼接顺序。2026-11-26 按 ComfyUI 裸写词表重排过一版：画质锚提前、构图从最后挪到衣服后面、姿势和动作合成一句。

| # | 层 | 含哪些选项 | 层内顺序 | 权重 |
|---|---|---|---|---|
| L0 | 画质 | 固定质量锚 | `best quality` | 不加 |
| L1 | 身份 | 人数头词 · 角色 trigger · 预设角色 feature · 原装衣服 | 头词 → trigger → 预设 feature → 原装 outfit_words | 头词不加权；trigger 1.15；feature 1.1；原装 1.0 |
| L2 | 身体 | 体型（`BODY_TYPES`）· 男性体型（`MALE_BODY_TYPES`）· 肉棒（`PENIS_SIZES`）· 纹身 | 男性体型 → 肉棒 → 女主体型 → 纹身位置 → 图案 → 发光 | 体型用自带权重，不再套；男性体型 1.0；肉棒 1.0；纹身 1.0 |
| L3 | 衣着 | 服装（`OUTFIT_SETS`）· 服装支 · 穿脱（`UNDRESS_PARTS` / `UNDRESS`）· 裸体 / 只穿内衣 · 淫水（`WET_LEVELS`） | 服装 → 穿脱 → 裸体替代词 → 淫水 | 服装 1.1；穿脱 1.0；裸体 1.1；淫水 1.0 |
| L4 | 构图 | 景别（`SHOTS`）· 角度（`ANGLES`） | 景别 → 角度 | 景别 0.95；角度 0.95 |
| L5 | 姿态 | 姿势 + 动作（合成一句）· 阶段（`STAGES`）· 体位补充（`ACTION_BOOST`）· 双人主动（`DUO_ROLE_TEXT`） | 姿势,动作 → 阶段 → 体位补充 → 双人主动 | 姿势句 1.0；阶段 1.05；boost 0.95；主动 0.95 |
| L6 | 互动 | 道具（`PROPS_*` + `PROP_USAGE`）· 手上动作（`HANDS_*`） | 道具 → 用法 → 手上 | 道具 0.95；用法 0.9；手上 1.0 |
| L7 | 面孔 | 表情（`EXPRESSIONS_*`）· 表情支撑（`EXPRESSION_SUPPORT`） | 表情 → 支撑 | 表情 1.25；支撑 1.05 |
| L8 | 环境 | 场景（`SCENES`）· 时间（`TIMES`）· 光线（`LIGHTS`） | 场景 → 时间 → 光 | 场景 1.0；时间 0.9；光 0.9 |
| L9 | 收尾 | `looking at viewer` · `detailed background` · 附加词 | 看镜头 → 背景 → 附加词 | 0.9 / 0.85 / 不加 |

### 与上一版的差别（2026-11-26 03:50）

- **画质锚 `best quality` 加在最前**：先定调，和 ComfyUI 手写习惯一致。
- **构图从最后提到 L4**：全身 / 半身 / 七分身是全局约束，放最后会被动作和场景词拉走近景；提上来之后动作词压不住构图。
- **姿势 + 动作合成一句**：原来是两条独立 tag，模型容易各画一半；合成 `sitting, reading` 这种短语后是一件事。
- **收尾单独成层**：`looking at viewer` 和 `detailed background` 是画面习惯，不该跟景别混在一起。
- 其余层（身体、衣着、互动、面孔、环境）的顺序沿用上一版：
  - 体型在服装前，身体先立住。
  - 淫水在衣着尾，描述的是下身状态。
  - 道具在表情前，`with xxx` 不打断人脸。
  - 环境内部 场景 → 时间 → 光。

## 三、互斥规则（每层一个说法）

### L1 身份
- 预设角色与角色 LoRA 互斥（已有）。
- 挂角色且没勾「覆盖角色体型」→ 体型层整个不出词（现有 `useBody`）。
- 原装衣服只在 `keepCharClothes` 为真时出；一有服装支就不再算原装。

### L2 身体
- 体型：只有「没挂角色」或「勾了覆盖」才出。
- 肉棒：仅成人 + 双人 + （性行为语境 或 明确选了尺寸）才出（现有条件）。
- 男性体型始终带在双人里，不因选了什么而缺。

### L3 衣着
- **全裸**：不出服装词、不出服装支、不出穿脱词；只保留 `socks only` 这种「裸但不全裸」的例外；负面加衣服压制（现有 `(clothes:1.3)…`）。
- **只穿内衣**：不出服装、不出 `topless / bottomless`（会跟「还穿着内衣」打架）。
- **穿脱**：按部位实际覆盖算（`outfitCoverage`），没穿的地方不脱；部位全脱且没有袜子 → 走裸体，而不是一条条 `topless, bottomless`。
- **服装支 vs 裸体**：互斥，服装支的词不带。
- **淫水**：只在性语境（`isSexualContext`）出；和「不流」互斥。位置在衣着层尾，不跟表情/背景混。
- 一条服装词里如果包含多个部位（`bikini, straw hat, sandals`），它算一条，不再拆。

### L4 姿态
- 姿势 × 动作按 `poseActionCompatible` 过滤，互斥的不能同时出现。
- 插入体位只接「贴着体位做」的动作（现有允许表）；
- 穿脱把衣服脱了 → 姿势里焊的衣服短语换成中性（`neutralizePoseForUndress`）；
- 选了手上动作 → 姿势里焊的手部短语摘掉（`neutralizePoseForHands`）；
- 动作支开着 → 姿势/动作两格都不出词（现有）。
- 阶段跟姿势动作自动走（`stageForAction`），和手选阶段互斥：手选优先，不兼容就回落自动。

### L5 互动
- 拿在手上的道具 × 手上动作互斥（`propHandCompatible`）；
- 道具 × 场景（`propSceneCompatible`）；
- 道具和裸体/穿脱冲突时以衣着为准，道具让位；
- 同样的短语只出现一次（`with cup` + `holding cup` 不能叠）。

### L6 面孔
- 表情必须出自当前模式的池（SFW/R18）。
- 支撑词只在表情命中 `EXPRESSION_SUPPORT` 时加，不重复表情本体。
- 表情是「不看镜头」那一类（闭眼 / 斜视 / 失神）→ 收尾不出 `looking at viewer`。

### L7 环境
- 场景 × 时间（`sceneTimeCompatible`）：雪地不配雨天，夜街不配白天；
- 光和场景打架 → 时间让位（现有）；
- 夜景场景 + 白天时间 → 删时间；
- 场景自带服装/姿势/双人动作的，仍走对应层，不另开一列。

### L8 镜头
- 景别 × 姿势（`poseShotCompatible`）；角度依赖景别，先定景别再筛角度；
- 背面机位不出 `looking at viewer`；
- 景别最具体的那条（特写类）优先，别同时出 `full body` 和 `upper body close-up`。

## 四、手选 / 随机补 的来源标记

`buildSixRecipe()` 里每个词记住来源，返回 `sources`：

| 来源 | 含义 | 位置 | 权重 |
|---|---|---|---|
| `user` | 用户在格子里明确选的 | 本层前部 | 按上表 |
| `auto` | 联动自动推出来的（阶段、体位补充、双人主动） | 本层中部 | 表内值 |
| `random` | 用户选「随机」，系统当场抽的 | 本层后部 | 表内值 × 0.95 |

「看最终词」按来源标色/加注释，用户能认出哪句是自己点的。这一步先只做标记，不改拼装结果。

## 五、落地改动点（不改选项内容）

1. `buildSixRecipe()` 的 `bits.push(...)` 顺序按上表重排，抽出八个小函数：`layerIdentity / layerBody / layerWear / layerPose / layerInteract / layerFace / layerEnv / layerCam`。
2. 权重统一走 `w(tag, n)`：tag 已带 `(` 或 `:` 时原样返回，否则套 `(tag:n)`。
3. `sources` 随 `recipe` 返回，`renderStage` 的「看最终词」按来源分组显示。
4. 后端 `buildPrompt()` 的 `joinTags` 去重保持不动；`cleanNegative` 规则不动（这次不碰负面）。
5. 不改 `PROP_USAGE` / `EXPRESSION_SUPPORT` / `BODY_TYPES` 的内容——这些属于第二步「选项内容」。
6. 每步改完跑：`node --check public/v2/app.js`、`_tmp` 出图区断言、同 seed 对比出图。

## 六、验收

- 三组固定配方，同 seed，改前 / 改后各出 4 张：
  1. 单人日常：女青年 + 校服 + 图书馆 + 坐着看书 + 柔和笑 + 白天
  2. 单人成人：成女 + 全裸 + 床上 + 张开腿 + 高潮 + 夜晚
  3. 双人成人：女青年 + 内衣 + 卧室 + 正常位 + 射脸上 + 夜晚
- 看四件事：衣服穿对没有、脸有没有被场景吃掉、姿势有没有被景别吃掉、同一维度有没有出现两次。
- 断言：prompt 里无 `undefined` / `NaN` / 断逗号；每层只出一个来源；裸体时无服装词；非性语境时无淫水词。

## 七、暂缓

- 选项内容本身的增删（词太泛、同义、过时）—— 等词路稳定后再做。
- 负面词重排 —— 这次不动，避免变量太多。

## 八、实现记录（2026-11-26 02:35–02:50）

已按本表落地，实际写法与表有两处出入，都是实现时定下的：

1. **多段词不加外层权重**。`w()` 遇到带逗号的整串原样返回，只有单段词套括号。理由是 `(a, b, c:1.1)` 在 ComfyUI 里语义不确定，而旧代码的服装 `(${outfit}:1.1)` 就是这么写的。结果：完整套装的衣服权重实际是 1.0，单件（`bikini`）才是 1.1。
2. **random 的权重按表 ×0.95**，但只作用于本来有基础权重的段；姿态、互动这类基础权重是 1.0 的段在 `w()` 里被当成「不加」。
3. 前端也做了一遍去重（`seenTags`），后端 `joinTags` 仍兜底。
4. 纹身从原来的「整条尾巴」挪到了 L2 尾（表里补上了）。

实测：

- 同一配方同 seed（20261126）改前 / 改后各 1 张，两张都正常；改后黑长裙下装比改前的高腰裤更明确，白衬衫、图书馆、窗光、笑脸都稳。
- 改前正面词：`1girl, solo, (white shirt:1.1), sitting, reading, medium breasts, …, (smile:1.25), library, window light, day, medium shot, looking at viewer, detailed background`
- 改后正面词：`1girl, solo, medium breasts, …, average build, (white shirt:1.1), sitting, reading, (smile:1.25), library, (day:0.9), (window light:0.9), (medium shot:0.95), (looking at viewer:0.9), (detailed background:0.85)`
- 24 条词路断言、17 条出图区断言，dev 和安装版各跑一遍，全过。
